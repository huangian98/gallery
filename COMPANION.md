# Offline Companion

This fork adds a Companion area to the home screen's side menu. It is a separate,
text-only conversation space: regular Gallery chats and tools are not read or
modified. Everything generated by Companion runs locally through LiteRT-LM.

## Use on Android

1. Build/install this fork (the stock Play Store Gallery does not include these changes).
   The APK uses this fork's debug signing key. If Android refuses to update a
   differently signed Gallery installation, use a separate test device/profile or
   export any important Gallery data before uninstalling the existing app.
2. Download Gemma 4 E2B through Gallery. E4B can also be selected if it fits in free
   RAM. Companion requires a `.litertlm` model, not GGUF, and does not download a
   second copy of the model.
3. Open the home screen menu → **Companion** → **Settings** and select your model.
4. Edit and save the personality and factual memories. Start a conversation in Chat.
   `/remember I like hiking` adds an explicit memory; `/forget I like hiking` removes
   matching memory lines. The editable memories field is the source of truth.
5. In Diary, choose **Write today's diary**, or enable the automatic nightly diary.
6. Optionally enable occasional check-ins and grant Android notification permission.
   Tap a notification to open the Companion conversation and reply.

The check-in test button runs immediately, even during quiet hours, and can still
choose silence. Chat with the companion before testing. Close any regular Gallery
chat model before using Companion; the runtime guard prevents two LiteRT chat
engines loading simultaneously. E2B is the suggested first choice on a 12 GB phone.

## Background behaviour

- Automatic check-ins and diary writing are both off by default.
- WorkManager checks approximately every three hours with a one-hour flex window.
  Battery must not be low; charging is required by default and can be switched off.
- Background inference skips while Gallery is in the foreground or another regular
  LiteRT chat model is loaded. Android may delay jobs or stop them; force-stopping
  the app prevents background work until it is opened again.
- Check-ins are eligible from 09:00 through 21:59 in the phone's current timezone.
  Each eligible cycle has a 40% chance of asking the model whether it has a useful
  follow-up. It can respond `SKIP` and send nothing.
- At most two check-ins per local calendar day, six hours apart. A check-in stops
  further check-ins until a user message is sent. Notification permission is needed
  for automatic check-ins. Diary work does not require notification permission.
- The nightly diary is eligible after 20:00 when there was a user conversation that
  day, with one saved entry per date. A missed night is not backfilled.
- Engines use CPU, text-only input, a 4,096-token context and a 384-token output cap,
  then close. No always-running model or foreground service is installed.

## Storage and memory

Personality, explicit facts, the latest 100 messages and up to 365 diary entries
are stored atomically in `noBackupFilesDir/companion.json`. They are excluded from
Android cloud backup/device transfer. No Companion data is sent to a server. This
is Android app-private storage, not additional application-level encryption.

Recent conversation context is supplied on each call. Long prompts are bounded,
and context overflow triggers a retry with a smaller UTF-8 budget so multilingual
history cannot grow unchecked. This first implementation
uses explicit, editable factual memories; it does not automatically extract facts
or search an unlimited history. Diary prose is never promoted to factual memory.
Diary entries are generated reflections, not a record of independent experience.

**Delete companion data** clears personality, facts, chats and diaries and cancels
automatic work. Downloaded models are retained. Uninstalling also removes Companion
data. Export is not yet implemented.

## Validation

From `Android/src` with the SDK/JDK required by the upstream project:

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

`CompanionPolicyTest` covers local-time quiet hours, opt-out, unanswered messages,
cooldown, per-day limits, diary eligibility, context bounds, diary/fact separation,
and the mutual exclusion guard. Device testing is still required for real model
loading, OEM background restrictions, notification permissions and thermal/battery
behaviour. Use E2B first and test with the screen off and charging.
